01 — Project Overview

Vision & Platform Purpose

Hotel365 is an AI-powered hospitality operations control platform for hotel management companies overseeing multiple branded properties (Hilton, IHG, Marriott, etc.). The platform's central innovation is a Proactive Task Engine — it automatically converts operational exceptions, KPI breaches, and anomalies into tracked, prioritized, assigned tasks. Staff are notified via in-app comments and alerts, eliminating the current reliance on manual Excel-based 365 reports.

Core Mission Statement Replace the daily manual grind of 29 check sheets, Excel workbooks and fragmented WhatsApp notifications with a single, intelligent, role-aware command center that proactively surfaces what needs attention — before revenue leaks.

Primary User Personas

🏢

Portfolio Owner / Management Company

Shreem Capital executives. Needs bird's-eye view across all properties. Revenue leakage dashboard, consolidated KPIs, compliance status, AI recommendations.

🏨

General Manager (On-Property)

Day-to-day hotel operations. Real-time exception alerts, Top 7 priority task list, rate integrity monitoring, overtime risk, actionable daily operations view.

👥

India Corporate Support Team

10-person team currently doing manual 365 data entry. Exception queue for review, AI-validated reports, reduced turnaround from hours to minutes.

🛎️

Department Heads (F&B, Housekeeping, Front Desk)

Department-level task views. Assigned task completion, escalation visibility, comment threads, due-date notifications.

02 — Brand Identity

Design System & Visual Language

Logo Treatment

The logo must read "Hotel365" or "HOTEL365" — rendered as a typographic mark, not an icon. The word Hotel is in pure white (#FFFFFF), and 365 is in Royal Orange (#E8670A). Use a classy serif or high-contrast display font (e.g. Playfair Display, Canela, or similar editorial serif). The number 365 can optionally use a bolder weight than "Hotel" for visual emphasis.

/* HOTEL365 DESIGN TOKEN SYSTEM */ --color-primary: #E8670A; /* Royal Orange — CTAs, tags, accents */ --color-primary-light: #FF8533; /* Orange hover / glow states */ --color-primary-glow: rgba(232,103,10,0.15); /* Subtle background wash */ --color-bg: #111111; /* True dark base */ --color-surface: #1A1A1A; /* Card / panel backgrounds */ --color-surface-raised: #222222; /* Elevated cards */ --color-border: #2E2E2E; /* Subtle separator lines */ --color-text-primary: #FFFFFF; /* Headlines, KPI values */ --color-text-secondary: #CCCCCC; /* Body copy */ --color-text-muted: #7A7A7A; /* Labels, metadata */ /* STATUS SYSTEM */ --status-critical: #E74C3C; /* Task overdue / revenue at risk */ --status-high: #E8670A; /* High priority — orange */ --status-medium: #F39C12; /* Medium priority — amber */ --status-low: #3498DB; /* Low priority — blue */ --status-done: #2ECC71; /* Completed — green */ --status-blocked: #9B59B6; /* Blocked — purple */ /* TYPOGRAPHY */ --font-display: 'Playfair Display', Georgia, serif; /* Logo, headings */ --font-body: 'DM Sans', 'Inter', sans-serif; /* All UI text */ --font-mono: 'JetBrains Mono', monospace; /* Values, codes */

Visual Principles

  • Dark-first UI: Charcoal black (#111) base. The dark theme communicates authority, reduces eye strain for long operational shifts, and makes orange accents pop.
  • Orange as signal: Orange is reserved for interactive elements (CTAs, badges, links) and high-attention items (critical alerts, revenue numbers). Never use it decoratively.
  • Information hierarchy: Big KPI numbers in white. Supporting context in #CCC. Timestamps, labels in #7A7A7A. This 3-tier system guides the eye without clutter.
  • Micro-border discipline: Cards have 1px #2E2E2E borders. Active/hover states shift to orange border. No drop shadows — use borders to define space.
  • Compact density: Hospitality GMs scan fast. Use 14px body text, 32-36px KPI numbers. Tables are dense but breathable with 8px row padding.

05 — Task Engine

Proactive Task Engine — Core Module

This is the #1 Priority Feature Every operational signal, exception, anomaly, and action item flows through the Task Engine. The platform's core moat is the Autonomous Execution Engine: Signal → Task → Completion → Impact → Learning.

Each task must render as a card or list row containing the following fields:

Task Views — Three Modes

A. Top 7 Priority View (GM Default)

A ranked list of the 7 highest-impact tasks for today. Sort by NOI Impact descending. Each item shows: rank number (1-7 in orange circle), task title, NOI at risk, assignee avatar, due time countdown, and status pill. One-click "Accept" / "Mark Done" / "Escalate" actions inline.

B. Kanban Board View

Columns: Pending In Progress Blocked Done. Drag-and-drop cards between columns (use HTML5 drag API or CSS pointer events). Each column shows count badge and total NOI at risk. Cards are color-left-bordered by priority.

C. List / Agenda View

Time-grouped list (Morning / Afternoon / Evening / Overdue). Compact rows with inline quick-action buttons. Sortable by: Due Time, NOI Impact, Department, Assignee. Search bar with real-time filter.

Task Sources — Auto-Generation Logic

The UI must show a "Source" badge on every task indicating which of the following 10+ signals created it:

  • Operations 365 Reports — 29 daily check sheets (Zero-rate rooms, High Balance, Guest Ledger, Adjustments, Void Tickets, etc.)
  • PMS Data Feed — Rate parity breaches, No-Show spikes, OoO room anomalies
  • GM Daily Standup — Voice/text input converted to tasks
  • Labor Analytics — Overtime threshold breaches, timecard discrepancies, schedule mismatches
  • F&B Monitoring — Open checks over 30min, void tickets above threshold, missing banquet postings
  • Accounts Receivable — Aging report exceptions, high-balance folios, chargeback alerts
  • Marriott Bonvoy / Loyalty — Certificate upload failures, points optimization opportunities
  • Rate Integrity — OTA rate parity violations ($500/day brand penalty exposure)
  • Procurement (Reeco) — Purchase anomalies, unapproved orders
  • Housekeeping Audit — Supervisor checklist exceptions, maintenance flags

Comment & Notification Thread

Each task has an expandable comment thread — similar to Slack or GitHub Issues. This is where staff communicate about the task, attach evidence, and record resolution notes.

COMMENT OBJECT SCHEMA { commentId: "CMT-001", taskId: "TSK-0042", author: "A.Angel", role: "Front Desk Manager", avatar: "AA", // initials fallback timestamp: "09:47 AM", type: "comment" | "status_change" | "system" | "escalation", text: "Called Acme Corp billing. They will wire by EOD.", attachments: [ ] }

Comment Thread UI Rules

  • System messages (auto-generated: "Task created by AI Engine from High Balance Report") appear as pill-style lines in muted text, not full comment bubbles.
  • Status changes render as timeline events: orange dot on a vertical line with "Status changed: Pending → In Progress by A.Angel at 09:47"
  • Human comments render as chat bubbles — user's own messages on right (orange bubble), others on left (dark bubble).
  • Input box at bottom with @mention support (type @ to suggest team members), emoji, and attachment icon.
  • Unread comment count shown as red badge on task card.

Notification Feed (Right Panel)

A live-scrolling notification feed in the right panel. Notifications are grouped into categories:

  • 🔴 Critical Alert — Immediate action required (rate parity breach, brand penalty at risk)
  • 🟠 Task Assigned — New task auto-generated and assigned to you
  • 🟢 Task Completed — A task you were watching was resolved
  • 💬 Comment — Someone replied in a task you're participating in
  • 📈 KPI Alert — Occupancy/ADR fell below threshold vs. forecast
  • ⏰ Escalation — Task overdue, escalated to next level

Alert Bell (Top Bar)

Bell icon in top nav with animated red badge showing unread count. Clicking opens a slide-in drawer (not a full page) with the last 20 notifications, grouped by Today / Yesterday / Earlier. Each notification has a one-click "Mark Resolved" button.

Delight Detail When a critical alert arrives, animate a subtle orange pulse ring around the bell icon for 3 seconds. Use CSS keyframes: @keyframes pulse-ring. This catches peripheral attention without being jarring.

09 — UX Principles

UX & Interaction Design Standards

The 3-Second Rule

A GM walking their property must be able to answer the question "What needs my attention right now?" within 3 seconds of opening the app. This drives every layout decision: Top 7 tasks must be visible above the fold, critical alerts must use color to create involuntary attention, and the most important KPI (Occupancy vs. Goal) must be readable without scrolling.

Interaction Standards

  • Hover states: Cards shift border-color to orange on hover. Subtle transform: translateY(-1px). Transition: 150ms ease.
  • Click feedback: Buttons scale to 0.97 on mousedown. Transition: 80ms.
  • Loading states: Use skeleton screens (animated dark-to-darker gradient pulse) not spinners. Skeleton blocks mirror the shape of actual content.
  • Empty states: If no tasks in a column, show a minimal illustration + "No tasks in this status. You're on top of it." in orange italic text.
  • Toast notifications: Slide in from bottom-right. Auto-dismiss after 4 seconds. Green for success, orange for warning, red for error. Never stack more than 3.
  • Responsive: Sidebar collapses to icon rail at <900px. KPI grid becomes 2 columns at <768px and 1 column at <480px. Task Kanban switches to vertical scrollable columns on mobile.

Anti-Patterns to Avoid (from Competitor Analysis)

  • ❌ No information overload — show relevant data for current role only, not everything at once
  • ❌ No buried value props — surface the dollar impact of every task and alert upfront
  • ❌ No generic loading spinners — use skeleton screens
  • ❌ No flat hierarchy in notifications — group and badge by urgency level
  • ❌ No tooltips-only mobile experience — all interactive elements must work with touch
  • ❌ No purple gradients, Inter/Roboto fonts, or typical SaaS aesthetics

Accessibility

  • All interactive elements must have keyboard focus rings (orange outline, 2px offset)
  • Color is never the only signal — all status badges also include text or icon
  • Minimum tap target size: 44x44px on mobile
  • ARIA labels on all icon-only buttons
